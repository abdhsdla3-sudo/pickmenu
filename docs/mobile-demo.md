# 모바일 앱형 데모

## 화면 흐름

인사 화면 → 프로필 4단계 → 추천 방식 선택 → 추천 결과 → 메뉴 상세

프로필은 신체정보, 식단 유형·영양 목표, 선호 음식, 알레르기·기피 재료 순서로 작성한다. 신체정보는 선택 입력이고 이번 데모에서 영양 목표 계산에 사용하지 않는다. 닉네임과 신체정보는 브라우저 저장소에만 저장한다. 추천 API에는 식단과 취향·제한 조건, 이번 식사 조건만 전달한다.

`pickmenu.profile.v2`를 저장 키로 사용한다. 이전 데모의 `pickmenu.profile.v1`은 처음 읽을 때 복원하고, 새 프로필 저장 시 v2로 옮긴다. 프로필 삭제 시 두 키를 지운다. 브라우저 저장소 사용이 막히면 해당 이용 중 메모리에서 프로필을 사용하고 안내한다.

## 두 추천 방식

- 선택지형은 저장 프로필에 이번 식사의 지역·영양 목표·음식군을 적용한다. 음식군은 `/api/catalog`의 실제 목록을 사용한다. 선택하면 `meal_category`로 정확히 필터링하고 해당 음식군에 선호 점수도 적용한다. 선택하지 않으면 범위를 제한하지 않고 저장한 취향을 반영한다. 이번 선택은 저장 프로필을 덮어쓰지 않는다.
- 대화형은 목표 → 맛·국물 → 메뉴명 순서의 질문과 빠른 답변을 제공한다. 같은 `POST /api/recommend`를 사용한다. 자유로운 LLM 추론은 향후 매장·LLM API 개발과 별도로 연결할 수 있다.

제한 조건의 필터와 참고 영양정보 정책은 메뉴 서버가 담당한다. 원재료가 확인되지 않은 후보와 추천 없음 상태도 두 흐름에서 동일하게 안내한다.
