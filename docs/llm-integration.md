# 로컬 GPU 연결 · 1.5.0

현재 데모: 브라우저 → 동일 출처 Ubuntu API → SSH 역방향 통로 → Windows Ollama(11435).
DB 조회와 메뉴·매장 선정은 Ubuntu에서 담당한다. Ollama는 인터넷에 공개하지 않는다.

Windows에서 `D:\학교\3학년\캡스톤\픽메뉴_서버관리\start-llm.cmd`를 실행한다.
Ubuntu `pickmenu-demo` 환경:

```ini
[Service]
Environment=PICKMENU_LLM_URL=http://127.0.0.1:11435
Environment=PICKMENU_LLM_MODEL=pickmenu-llm:8b
```

- `POST /api/chat`: `messages`(최대 6개 사용자 발화, 각각 300자), `profile`(기존 추천 조건).
  `reply`, `conditions`, `result`를 돌려준다. 로그인 정책은 기존 추천과 같다.
- 모델은 조건을 정리하고 서버가 문장과 대조해 고친다(1.6.5).
  - 목표·맵기·국물: 문장에서 가장 뒤에 나온 표현을 따른다. "매운 건 싫어", "맵찔이", "국물업는거",
    "탕 말고"처럼 부정한 표현은 반대 값이 된다. 국물 부정은 국물 바로 뒤만 보므로 "국물 요리로, 파 싫어"는 국물 있음이다.
  - 음식군: 목록에 있는 값이고 그 음식군을 가리키는 말이 문장에 있을 때만 쓴다("국밥 중에서" → 국밥·해장국).
    문장에 없는 음식군("국물 없는 거" → 국밥·해장국)은 버린다.
  - 메뉴명은 발화에 나온 이름을 우선 적용한다. v1.8.3부터 대표 메뉴와 연결되는 오타·줄임말·등록된 영어 별칭·여러 턴의 꾸밈말에는 모델이 낸 보정값을 쓸 수 있다. 제외된 메뉴와 근거 없는 보정은 버린다.
  - 알레르기·기피 재료: 재료 바로 뒤에 '알레르기'(→ 알레르기)나 '싫어·빼 줘·안 들어간·못 먹어·별로'(→ 기피)가
    있어야 남긴다. "음 회 땡겨"의 '음', "고기 요리"의 '고기', "안 매운 걸로"의 '매운'은 버린다.
  - 이 검증은 제한된 한국어 표현을 지원한다. 화면에 표시된 적용 조건을 확인해야 한다.
- 이전 조건과 제한 재료를 다음 요청에 유지한다. 대화는 브라우저 메모리에서만 유지하며,
  로그아웃·다시 시작 시 지운다. 최대 회수 후 대화를 조용히 버리지 않고 다시 시작을 안내한다.
- 메뉴 선정은 기존 `recommend`와 `standard_menu_id`로 수행한다. 모델이 SQL을 생성하거나
  DB를 직접 조회하지 않는다. 알레르기 안전 여부와 영양 수치를 추측해 필터를 완화하지 않는다.
  이미 먹었다고 한 메뉴는 이번 추천에서 제외한다. 같은 메뉴를 또 먹고 싶다고 하면 마지막 요청을 적용한다.
  재료 확인이 안 된 후보가 있으면 답에 주문 전 가게 확인 안내를 붙인다. 서버는 맛 표현을 찾아 `taste`로 넘긴다(부정하면 `-`로 시작). 기름지지 않은 음식을 원하면 100g당 지방 참고값을 우선하고, 튀기기·찌기·삶기·데치기는 선호 점수를 보정한다. 굽기·볶기·끓이기로는 기름 사용량을 추정하지 않는다. 추천 이유에 공개 참고 레시피와 대표 메뉴명 추정을 구분한다. 가벼운 식사 점수에는 열량·나트륨과 1인분 참고량을 사용하고, 1인분 정보가 없는 메뉴에는 100g 비교라고 표시한다. 다른 맛 표현에는 이름과 분류의 단서를 사용한다. 맛 표현만 있는 검색어("새콤한")는 버린다.

  공개 참고 레시피 조리법은 `python -X utf8 drive_data.py`로 Drive 자료를 다시 읽고 `python -X utf8 prepare.py --build-only`로 카탈로그를 갱신한다. 연결이 승인된 공개 일반 레시피를 단품의 표준 메뉴 ID로 연결한다. 이 값은 매장 자체 레시피의 확인 여부를 나타내지 않는다.
- `/api/recommend/stores`의 상위 10개 매장 추천이유는 두 부분이다(1.8.0).
  - 사실 문장(`comment_facts`): 서버가 정해진 문장으로 쓴다. 이 메뉴 리뷰 중 이 가게의 몫(카탈로그 trace),
    참고자료 DB의 가게 단골 주문 비율(재주문 표본 20건 이상), 만족한 리뷰 비율(리뷰 10건 이상, 80% 이상일 때),
    양 리뷰 판정('많음'일 때) 중 기준을 넘는 것을 최대 2개 쓰고 줄마다 두 번째 근거를 바꾼다.
    리뷰 수는 바로 위 줄에 보이므로 다시 말하지 않는다. 리뷰 5건 미만이면 "아직 리뷰가 적어" 안내만 쓴다.
  - AI 한마디(`comment_mood`): 모델에는 메뉴 이름과 구만 보내고, 숫자 없는 6~28자 분위기 말
    ("쌀쌀한 저녁 한 그릇으로")만 받는다. 숫자·리뷰·손님·단골·가게 이야기, 기존 금지어, 자주 반복되던 말
    (퇴근길·고민·다녀갔 등), 같은 응답 안에서 겹치는 한마디는 버린다. 통과하지 못하면 사실 문장만 보여 준다.
    둘러보기(로그인 전) 요청은 모델을 부르지 않는다.
  - 1.8.3: 메뉴마다 다른 상황(scene, 예: 비 오는 날·과제 끝낸 날)을 하나씩 건네 '[상황] + 기분·동작' 꼴로 쓰게 하고,
    한 응답 안에서 같은 낱말은 두 번까지만, 프롬프트 예시를 그대로 베낀 한마디는 버린다. 실제 모델 측정은
    `pickmenu/eval/store_mood_eval.py`로 다시 할 수 있다(통과율·고유 비율·자주 쓴 낱말).
  - 8B 모델에 숫자까지 맡기면 "6명 중 10명"처럼 틀린 문장이 나와 이렇게 나눴다. `comment`는 두 부분을 합친 값이다.
  리뷰 수와 단골 비율은 평점이 아니다. AI 한마디의 적절성은 완전히 보장되지 않는다.
- 꾸밈말 메뉴와 빼기(1.9.0)
  - 기본 메뉴와 꾸밈말을 따로 말하면 꾸민 메뉴로 찾는다("치킨 … 양념" → 양념치킨). 꾸밈말 목록은 대표 메뉴 이름에서 자동으로 만든다.
  - "중식 말고", "면 빼 줘", "밀가루 음식 말고"는 `exclude_categories`·`exclude_groups`가 된다. 음식 묶음은
    `pickmenu/story_groups.json`에 있다. words는 사용자가 쓰는 말, categories는 통째로 뺄 음식군, names는 메뉴 이름 단서다.
  - 이 파일을 고치면 단위 시험과 `eval/story_regression.py`를 돌린다.
- 이야기 추천 회귀 시험(1.8.9): `pickmenu/eval/story_regression.jsonl`에 2,325문장과 기대 조건, 문장마다 기록된
  AI 원본 조건이 있다. 다섯 시험셋을 합쳤다.
  - 상황추론 128
  - 새말투 138
  - 생성문장 1,035
  - Codex 대규모 804
  - Codex 인터넷 말투 220

  `pickmenu` 폴더에서 `PYTHONPATH=. .venv/bin/python -X utf8 eval/story_regression.py`로
  기록된 AI 조건을 그대로 넣고 서버 규칙만 다시 돌려 채점한다(약 40초).
  - 기준 점수(`eval/story_baseline.json`)에서 맞던 문장이 틀리면 목록을 보여 주고 종료 코드 1을 낸다.
  - 의도한 변화면 `--write-baseline`으로 기준을 갱신한다.
  - `--model pickmenu-llm:8b-ft-q8`는 파인튜닝 모델 기록을 쓴다. 기록이 없는 문장은 데모 모델 기록을 쓴다.
  - `--live`는 실제 AI를 다시 부른다.

  기대 형식은 두 가지다. strict는 적지 않은 칸이 저장 프로필 그대로여야 한다. listed는 적은 칸만 보며, 빈 값은 조건을 풀어야 한다는 뜻이다.
  이 시험셋으로 규칙을 고친 적이 있어 점수는 처음 보는 문장보다 높게 나온다.
- 동시 모델 호출 1개, 호출당 35초 제한, 최대 출력 1536토큰. 다른 요청이 처리 중이면 대화는
  재시도를 안내하며 매장 설명은 생략한다. 선택지 메뉴 추천은 모델을 호출하지 않는다.
- 이름·생년월일·성별·키·몸무게·계정 토큰은 모델에 보내지 않는다. 대화에 직접 쓴 내용은
  모델 입력이 되므로 불필요한 개인정보를 입력하지 않는다. 요청 원문을 로그에 남기지 않는다.
- 클라우드 이전: 동일 Ollama API와 모델을 GPU 서버에 설치하고 `PICKMENU_LLM_URL`만 사설
  GPU 주소로 교체한다. 다른 호스트로 나갈 때 TLS·서비스 인증 또는 사설 SSH 통로를 적용한다.

현재 공개 Sites Worker에는 인증·대화 API가 연결되지 않았다. 이 기능의 배포 대상은 Ubuntu 데모다.
