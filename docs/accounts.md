# 회원 계정과 로그인

0.4.0부터 아이디·비밀번호로 가입하고 로그인할 수 있다. 로그인하지 않아도 지금처럼 브라우저 프로필로 추천을 받을 수 있다.

## 저장하는 정보

| 위치 | 내용 |
| --- | --- |
| 서버 `users` 표 | 아이디, scrypt 비밀번호 해시, 닉네임과 취향·알레르기·기피 재료 프로필 |
| 서버 `sessions` 표 | 로그인 토큰의 SHA-256 해시와 만료 시각(30일) |
| 브라우저 | 기존 `pickmenu.profile.v2` 프로필. 나이·키·몸무게는 서버에 보내지 않는다 |

계정 DB는 `PICKMENU_USERS_PATH`로 지정하고, 없으면 `pickmenu/local/users.sqlite3`를 만든다. 운영 서버에서는 체크아웃 밖의 경로를 지정하고 서비스 계정만 읽고 쓰게 권한을 둔다. DB 파일은 Git에 커밋하지 않는다(`*.sqlite*` 무시 규칙).

## API

| 요청 | 설명 |
| --- | --- |
| `POST /api/auth/signup` | `{username, password}`로 가입하고 바로 로그인한다. 아이디는 영문 소문자·숫자·밑줄 4~20자, 비밀번호는 8~64자. 중복이면 409 |
| `POST /api/auth/login` | 로그인. 틀리면 401, 같은 아이디로 5회 실패하면 5분간 429 |
| `POST /api/auth/logout` | 세션을 지우고 쿠키를 만료한다 |
| `GET /api/auth/me` | `{user, profile}`. 로그인하지 않았으면 `user`가 `null` |
| `PUT /api/profile` | 로그인 사용자의 프로필 저장. 허용한 항목만 저장한다 |
| `DELETE /api/profile` | 계정에 저장한 프로필 삭제 |

세션 쿠키 `pickmenu_session`은 HttpOnly, SameSite=Lax다. HTTPS로만 제공하는 운영 환경에서는 `PICKMENU_COOKIE_SECURE=1`을 지정해 Secure 속성을 붙인다. 상태를 바꾸는 요청은 JSON 본문을 요구해 다른 사이트의 폼 전송을 막는다.

## 화면 흐름

- 상단 `로그인` 버튼, 인사 화면의 `로그인하고 불러오기`, 하단 `계정` 메뉴에서 계정 화면을 연다.
- 가입하거나 로그인하면 계정에 프로필이 있을 때 불러오고, 없으면 이 브라우저의 프로필을 계정에 옮긴다. 둘 다 없으면 프로필 작성을 시작한다.
- 로그인 상태에서 프로필을 저장하거나 삭제하면 계정에도 반영한다. 서버 저장에 실패하면 브라우저에는 저장하고 실패를 안내한다.
- 로그아웃하면 공용 기기 보호를 위해 이 브라우저의 프로필도 지운다.

## 남은 일

- Sites 공유본(`pickmenu-share/worker.js`)은 메뉴 API 세 경로만 전달한다. 공개 사이트에서 로그인을 쓰려면 계정 경로 전달과 쿠키 처리를 별도로 붙인다.
- 비밀번호 찾기·변경, 회원 탈퇴, PostgreSQL 이전은 아직 없다.
