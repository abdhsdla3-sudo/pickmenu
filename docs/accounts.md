# 회원 계정과 로그인

0.4.0부터 아이디·비밀번호로 가입하고 로그인할 수 있다. 0.6.0부터 취향 설정·메뉴 추천·메뉴 상세는 로그인이 필요하다. 로그인 전에는 시작 화면·로그인·회원가입 화면을 제공한다. 서버에서도 추천·상세 API의 세션을 검사한다.

## 저장하는 정보

| 위치 | 내용 |
| --- | --- |
| 서버 `users` 표 | HMAC 아이디·마스킹 표시값, scrypt 비밀번호 해시, 암호화한 기본정보·취향 프로필 |
| 서버 `sessions` 표 | 로그인 토큰의 SHA-256 해시와 만료 시각(30일) |
| 브라우저 | 로그인 중 메모리에만 프로필 표시. 이전 localStorage 프로필 캐시는 삭제 |

계정 DB는 `PICKMENU_USERS_PATH`로 지정하고, 없으면 `pickmenu/local/users.sqlite3`를 만든다. 운영 서버에서는 체크아웃 밖의 경로를 지정하고 서비스 계정만 읽고 쓰게 권한을 둔다. DB 파일은 Git에 커밋하지 않는다(`*.sqlite*` 무시 규칙).

Ubuntu 웹 서비스에는 `PICKMENU_REQUIRE_LOGIN=1`을 설정해 추천·상세 API도 로그인 세션을 요구한다. 이 설정을 생략한 독립 메뉴 API는 기존 호출 호환성을 유지한다. 웹 화면 자체는 항상 로그인 후 이용하도록 안내한다.

## API

| 요청 | 설명 |
| --- | --- |
| `POST /api/auth/signup` | `{username, password, profile}`로 가입하고 바로 로그인한다. 웹에서는 birth_date·height·weight·gender 필수, nickname·취향 선택. 기존 age 입력도 호환한다. 아이디 4~20자, 비밀번호 8~64자. 중복이면 409 |
| `POST /api/auth/login` | 로그인. 틀리면 401, 같은 아이디로 5회 실패하면 5분간 429 |
| `POST /api/auth/logout` | 세션을 지우고 쿠키를 만료한다 |
| `GET /api/auth/me` | `{user, profile}`. 로그인하지 않았으면 `user`가 `null` |
| `PUT /api/profile` | 로그인 사용자의 프로필 저장. 허용한 항목만 저장한다 |
| `DELETE /api/profile` | 계정에 저장한 프로필 삭제 |

세션 쿠키 `pickmenu_session`은 HttpOnly, SameSite=Lax다. HTTPS로만 제공하는 운영 환경에서는 `PICKMENU_COOKIE_SECURE=1`을 지정해 Secure 속성을 붙인다. 상태를 바꾸는 요청은 JSON 본문을 요구해 다른 사이트의 폼 전송을 막는다.

## 화면 흐름

- 상단과 시작 화면에 `로그인`·`회원가입` 버튼을 각각 표시한다. 선택한 화면의 제목과 제출 버튼이 바뀌며 화면 안에서도 두 작업을 전환할 수 있다.
- 가입하거나 로그인하면 계정에 저장된 프로필을 불러오고, 없으면 취향 설정을 시작한다. 로그인 전에 남아 있던 브라우저 프로필을 다른 계정에 자동 업로드하지 않는다.
- 로그인 상태에서만 `내 취향 알려주기`·`저장된 프로필로 시작하기`를 표시한다. 세션 확인 실패나 추천 API의 401 응답 시 로그인 화면으로 돌아간다.
- 1.1.0부터 닉네임이 없으면 자동 생성하고 계정 설정에서 변경할 수 있다. 생년월일로 만 나이를 표시하며 가입·조회 시 서버에서 다시 계산한다. 생년월일도 암호화해 저장한다.
- 1.0.0부터 가입 기본정보와 선택 취향을 계정에 암호화해 저장한다. 기존 회원은 로그인 후 누락된 기본정보를 보완한다. 자세한 저장·키·이전 절차는 [개인정보 보호 안내](account-privacy.md)를 따른다.
- 로그인 상태에서 프로필을 저장하거나 삭제하면 계정에도 반영한다. 서버 저장에 실패하면 화면 메모리에 유지하고 실패를 안내한다.
- 로그아웃하면 공용 기기 보호를 위해 이 브라우저의 프로필도 지운다.

## 남은 일

- Sites 공유본(`pickmenu-share/worker.js`)은 메뉴 API 세 경로만 전달한다. 공개 사이트에서 로그인을 쓰려면 계정 경로 전달과 쿠키 처리를 별도로 붙인다.
- 0.6.0 화면의 공개 Sites 배포는 계정 API 연결이 완료된 뒤 진행한다. 이번 배포 대상은 Ubuntu의 Tailscale 서비스다.
- 비밀번호 찾기·변경, 회원 탈퇴, PostgreSQL 이전은 아직 없다.
