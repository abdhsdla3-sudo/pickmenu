## Windows CMD 재실행

Python 3.11 이상과 기존 `requirements-preprocess.txt`의 openpyxl만 사용한다. 경로는 큰따옴표로 감싼다. 저장소 루트에서 실행한다. 아래 예시에서는 갱신 파일을 `pickmenu/local/updates/`에 둔다. 원본 DB는 기존 `prepare.py` 전수 처리 결과여야 한다.

```bat
chcp 65001 > nul
cd pickmenu
python -X utf8 refresh.py --source-db "%CD%\local\catalog.sqlite3" --updates "%CD%\local\updates" --output "%CD%\local\catalog-v03.sqlite3"
set "PICKMENU_CATALOG_PATH=%CD%\local\catalog-v03.sqlite3"
set "PICKMENU_AUDIT_DIR=%CD%\local"
start.cmd --port 8767
```

`http://127.0.0.1:8767/`로 접속하고 `Ctrl+C`로 종료한다. 이후 실행은 두 환경변수 설정과 `start.cmd`만 필요하다. 출력 DB와 `.audit.json`은 Git에 올리지 않는다. 출력 경로가 원본 DB와 같으면 실패하도록 했다. 임시 DB에서 처리·무결성 검사한 뒤 교체하므로 실패 시 기존 결과가 보존된다. 실패 후 같은 명령으로 갱신 단계를 다시 실행한다(이 작은 갱신 단계는 파일 중간부터가 아니라 전체를 재검사). 두 차례 같은 입력으로 실행하여 카탈로그 논리 SHA-256과 7,780개 매핑이 동일하고 중복 누적이 없음을 확인했다.

음식군 선택은 `/api/catalog`의 20개 실제 음식군을 표시한다. 선택한 값은 API의 `meal_category`로 정확히 필터링한다. `category` 취향 점수와 자유 검색 `query`와 구분한다. 후보가 없으면 다른 음식군을 몰래 추천하지 않는다. 저장 프로필은 수정하지 않는다.
