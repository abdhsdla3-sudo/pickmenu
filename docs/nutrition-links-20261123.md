# 영양정보 검수 연결 (1.10.0, 2026-11-23)

데이터 팀의 2026-11-23 조사 자료로 영양정보가 비어 있던 메뉴 일부를 연결했다. 개발용 카탈로그 사본에만 적용했다. 운영 사이트는 아직 바꾸지 않았다.

## 무엇을 검수했나

- 대표음식 88개 추가 조사에서 '수치 연결 후보'로 분류된 **45개 대표음식**을 모두 봤다. 실행 카탈로그(2,536개)에서 이들은 **표준 메뉴 136개**다.
- 대표음식 이름만 보고 일괄로 붙이지 않았다. 표준 메뉴마다 실제 메뉴명, 판매 매장 브랜드, K-FIND 원본 행(식품기원명·업체명·기준량·수치)을 대조했다.
- 1,700개 연결근거의 기존 판단('가공식품 비교 후보', '공식 원수치 일치 · 실제 메뉴명 대조 필요' 등)을 같은 표준 메뉴 ID로 합쳐 기록했다. 1,700개 전체의 상태는 자동으로 올리지 않았다.
- 치킨 근거 2건도 함께 처리했다. 허니버터치킨은 옵션별로 보여 주고, 순살양념치킨은 보류했다.
- 29개 유형 확인 후보, 11개 조리·구성 근거, 3개 부분 근거는 이번 수치 연결 대상이 아니다.

## 구현

- `pickmenu/nutrition_approvals.json`: 검수 결정(승인·보류, 종류, 식품코드, 이유). 원본 조사 자료의 내부 경로와 리뷰 원문은 넣지 않았다.
- `pickmenu/nutrition_links.py`: 원본 카탈로그를 읽기 전용으로 열고 다른 경로에 새 카탈로그를 만든다.
  - 승인된 식품코드를 K-FIND 음식 원본 CSV에서 다시 읽는다. 일반 음식이 분석값이 아니거나, 제품의 업체명이 다르거나, 기준량이 100g·100mL가 아니면 멈춘다.
  - 값은 `references`에만 더한다(`kind`: general·product·product_option). 추천 점수가 쓰는 `nutrition`은 바꾸지 않고, 바뀌면 멈춘다.
  - 원문 단위(100g·100mL)를 그대로 두고 1인분으로 바꾸지 않는다. `serving_reference`는 비운다. 빈 수치는 null이다.
  - 같은 메뉴에 같은 식품코드·옵션이 있으면 다시 붙이지 않는다. 카탈로그 안 `nutrition_link_log` 표와 `*.nutrition-audit.json`에 추가·보류 ID를 남긴다.
- 화면(`web/app.js`): 카드 한 줄과 메뉴 상세에서 '일반 음식 참고값', '해당 제품 기준', '해당 브랜드 제품 · 옵션별 · 판매 옵션 미확정', '출처가 제시한 조사 제공량'을 구분한다. 예전 자동 연결 값의 표시는 그대로다.
- 공유 내보내기(`pickmenu-share/export.py`)도 새 칸을 함께 내보낸다.

## 검증

- 같은 입력으로 두 번 만든 카탈로그와, 결과 카탈로그에 다시 적용한 카탈로그의 논리 SHA-256이 모두 `a41fbe9a…0246`으로 같았다(다시 적용 때는 6건 모두 '이미 연결됨').
- 추천 순위: 영양 목표 3 × 지역 5 × 음식군 21 × 맵기·국물 3 = 945개 조건에서 기존 카탈로그와 새 카탈로그의 선택지 추천 메뉴·점수가 모두 같았다. 알레르기·채식 판정은 `references`를 읽지 않는다.
- 단위 테스트 7개 추가(일반·제품·옵션, 결측 null, 100mL 단위, 가공식품·급식·다른 브랜드 거부, 재실행, 조사 제공량 분리, 승인 목록 정책). 전체 unittest 139개, ruff, mypy, `node --check` 통과.
- 개발용 임시 서버(375px)에서 위 조회 예의 메뉴 상세와 카드 문구를 확인했다. 기존 프랜차이즈 매장 카드(굽네 등 37곳 중 35곳 연결)와 기존 자동 연결 참고값 표시가 그대로였다. 콘솔 오류 없음.

## 운영 반영 순서 (승인 후)

VM에서 릴리스 폴더 방식으로 한다. 입력은 지금 운영 카탈로그, 승인 목록, K-FIND 음식 CSV, 대표음식 조사 JSON이다.

```sh
cd ~/pickmenu-releases/v1.10.0/source/pickmenu
src=~/.local/share/pickmenu/nutrition-src-20261123
~/pickmenu/pickmenu/.venv/bin/python -X utf8 nutrition_links.py \
  --catalog ~/pickmenu-releases/v1.8.6/catalog.sqlite3 \
  --food-csv "$src/식품의약품안전처_통합식품영양성분정보(음식).csv" \
  --research "$src/픽메뉴_대표음식_공개영양과_레시피_조사_20261123.json" \
  --output ~/pickmenu-releases/v1.10.0/catalog.sqlite3
```

1. `v1.9.3/deploy.sh` 형식으로 `v1.10.0` 폴더를 만들고 위 카탈로그를 `PICKMENU_CATALOG_PATH`로 지정한다.
2. `--check`로 메뉴 수(2,536), `nutrition_link_log` 추가 6건, 위 조회 예 화면을 확인한 뒤 `--apply`한다.
3. 되돌리기: 이전 릴리스(v1.9.9 이하) 설정으로 `--rollback`한다. 이전 카탈로그 `v1.8.6/catalog.sqlite3`는 바꾸지 않으므로 그대로 쓴다.
4. Sites 공유본을 쓰는 경우 새 카탈로그로 `pickmenu-share/export.py`를 다시 실행한다.

생성 카탈로그·감사 파일·원본 CSV·조사 JSON은 Git에 올리지 않는다.
