# 전체 점검과 발전 방향 (2026-11-19, 1.6.14 기준)

코드(Python 약 3,300줄, 웹 1,700줄), 문서, 참고자료 DB(`pickmenu_data` v1.4), 팀 평가 결과(선택지 77,490개 조합,
대화 548개, 매장 코멘트 1,172개)를 함께 보고 정리했다. 운영 카탈로그는 서비스 계정 파일이라 직접 열지 못했다.

## 지금 잘 되어 있는 것

- 추천 계산과 AI가 분리되어 있다. 메뉴 선정은 서버 규칙, AI는 조건 정리와 한마디만 맡고 서버가 다시 검사한다.
- 개인정보 보호: 아이디 HMAC, 프로필 암호화, 위치 미저장, 로그 정리, 신체정보를 AI에 보내지 않는다.
- 추천 근거가 화면에 나온다(리뷰 수·만족도·단골 주문·감점 이유). 테스트 88개가 규칙을 고정한다.

## 부족한 점 (우선순위 순)

### 1. 데이터와 검증

| # | 문제 | 영향 | 제안 |
|---|---|---|---|
| 1 | 개발 계정이 운영 카탈로그(`catalog-v03.sqlite3`)를 읽을 수 없다 | 실데이터 테스트 6개가 늘 건너뛰어지고, 규칙을 바꿔도 실제 결과 변화를 잴 수 없다 | 읽기 전용 사본을 `pickmenu-dev` 그룹이 읽을 수 있는 위치에 두기 |
| 2 | 평가 스크립트(77,490 조합·548 대화·코멘트 표본)가 저장소에 없다 | 다음 수정 때 같은 측정을 다시 할 수 없다 | `pickmenu/eval/`로 옮기고 결과 요약만 커밋(원본 리뷰·대화 원문 제외) |
| 3 | 영양 점수가 100g 기준이다. 1인분 양과 **나트륨은 점수에 쓰지 않는다** | 양이 많은 메뉴와 짠 국물 메뉴가 건강 점수에서 불리하지 않다 | 참고자료 `portion_g`·`rice_included`로 1인분 환산, 나트륨 감점은 평가 스크립트로 영향을 잰 뒤 적용 |
| 4 | DB 매장 메뉴 31%(385줄)에 영양 점수가 없다 | 기준표대로 중앙값 처리되어 차이가 줄어든다 | 데이터 담당 보강 대상 목록으로 넘기기 |
