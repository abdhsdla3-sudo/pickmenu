# 픽메뉴 데이터 인벤토리와 검증 결과

이 문서는 초기 전수 처리의 기준 기록이다. 현재 0.3.0 공유 데모에는 [2026-11-14 수정 자료 반영](../docs/data-update-20261114.md)을 추가 적용해 2,536개 메뉴를 사용한다. 아래 초기 5,736개 카탈로그 수치와 구분한다.

## 로컬 원본과 Drive 대조

작업 공간의 원본 ZIP에는 기간별 CSV 5개와 수원 배달음식 기획초안 PDF 1개가 있다. 모두 로컬 파일과 크기와 CRC32가 같다. 원본 ZIP은 중복 입력에서 제외했다. Drive 폴더 2개와 파일 43개는 로컬 원본 ZIP 목록과 달랐다. Drive의 수원 전체리뷰는 원본에서 가져온 부분집합이다. 유효 원본 행 순번·플랫폼·구·메뉴 배열과 원본 14개 필드 해시가 121,150건 모두 일치한다.

원본 CSV는 UTF-8이다. 사업자번호와 플랫폼 값은 식별용 문자열, 별점은 0~5 수치 또는 결측 표시, 주문횟수는 정수 또는 결측, 메뉴는 JSON 문자열 배열로 확인했다. KST는 제공 설명에 따라 원문을 UTC로 가정해 9시간을 더했다. 원본 전수 검사는 모든 기간과 플랫폼을 포함했다. 추천에는 검증된 수원 4개 구와 2026년 7~9월 KST만 사용했다.

## 매핑·제외·추적

- 제공 매장 ID는 정규화 사업자번호·전체 주소·가게명 조합이다. 사업자번호 단독이나 가게명 단독으로 합치지 않았다. 646개 매장 ID의 지역을 대조했다. 리뷰 121,150건 중 대표 119,582건을 사용했다. 중복 표시 1,568건은 원본 참조를 남겼다.
- 제공 메뉴 배열을 파싱하고, 메뉴 연결표의 음식·음식 검토 역할을 매장 ID와 리뷰 ID로 연결했다. 165,653개 메뉴 연결에서 역할 외 13,351행, 대표·고유 키 조건을 충족하지 못한 2,522행을 제외해 149,780개 고유 리뷰×메뉴 연결을 만들었다. 매장×메뉴 집계와 13,801개 조합이 일치했고 차이가 난 1,133개 조합은 모두 음료였다.
- 최종 음식 분류표 7,977개에서 식사 범위 밖(음료·카페 음료·디저트·사이드), 미분류, 지역 근거 없음 등으로 2,241개를 제외했다. 식사 추천 카탈로그는 5,736개다. `catalog.id → trace.menu_id → review.review_id → review.source_file/source_row`로 원본까지 추적한다. `trace.original_name`과 `trace.menu_position`에서 원본 메뉴명을 확인할 수 있다.
- 카탈로그 5,736개 중 1,535개에 검증한 참고값이 있고, 1,155개가 단품 영양 점수에 사용된다. 나머지 380개의 참고값은 구성 음식 기준으로만 표시한다. 4,201개는 표시할 수 있는 100g 참고값이 없다. 단품으로 분류됐더라도 제목에 세트·정식 등의 표지가 있으면 전체 메뉴 점수를 계산하지 않는다.
- 영양은 제공 결합표 → 음식종류 연결표 → K-FIND 음식 CSV의 식품 코드·이름·g 기준량·100g 환산 수치를 대조했다. 예를 들어 `아구찜` 계열은 식품코드 `D307-338000000-0002`, `아귀찜`, 100g당 78 kcal 및 단백질 12.08 g이다. 자동 동의어 매핑이며 매장 레시피 및 제공량은 미검증이다. 사람이 승인한 매장 매핑은 0건이다.
- 참고 레시피, 가공식품, 원재료, 수산물, 건강기능식품 및 기관별 통합 자료는 키·스키마·결측을 검사했다. 레시피는 기준량 미확정이며 다른 분류의 파일은 제공 음식 연결 출처 범위 밖이라 해당 수치를 추천에 쓰지 않았다. 리뷰 감성 자료와 재주문 CSV는 ID·분포·후속 연결을 점검했으며 순위에는 넣지 않았다. `order_count`는 리뷰에서 관측된 플랫폼 제공 값으로, 전체 고객 재구매율을 계산하는 데 필요한 정의와 분모가 확인되지 않았다.

집계와 파일·시트별 키 검증 수는 [카탈로그 감사](local/build-audit.json)에 있다. 내려받은 Drive 파일과 생성 DB·로그는 `local/` 아래에 보관한다. 리뷰 작성자 정보는 웹 응답에서 제외했다.

## 참조 자료 적용

- 픽메뉴 발표 자료는 텍스트 레이어가 없어 20쪽을 이미지로 렌더링해 읽었다. 프로필·추천·선택의 화면 흐름과 수원 리뷰 분석 기준을 사용했다. 개발 기획서의 분리된 식단 유형·영양 목표와 표준 메뉴 ID 계약을 적용했다.
- 캡스톤의 이전 추천 점수 가이드와 채팅은 제한 필터, 비교 단위, 결정적 정렬과 음식군 다양성 규칙에 반영했다. 개발 기획 및 이전 논의의 역할 경계를 따라 매장 후보의 연결 근거를 정리했다.

## 검증 결과

- 실제 데이터 및 단위 테스트 10개 통과. 원본/Drive 전체 행 수 대조, UTF-8, JSON 파싱 실패 분기, 엄격 제한, 영양 결측과 비교 단위, 동률 재현, 0개 및 부족 후보, DB 오류, 원본 근거 추적을 검사했다.
- Ruff, mypy, Python `compileall`, Node `--check` 통과. 브라우저는 정적 파일을 직접 불러온다.
- 데스크톱 1280px과 모바일 390px에서 추천, 상세, 프로필 저장 및 새로고침 복원, 수정, 초기화를 확인했다. 모바일 한 열과 가로 넘침 없음, 한국어 표시를 확인했다.
- 기본 요청 5개, 비건·단백질 중심과 돼지고기 제외 요청 0개를 확인했다. 영통구에서 비빔밥으로 다시 검색해 메뉴 상세를 확인했다.
- 영통구의 후라이드 반반 검색으로 후보 1개와 영양정보 없음 안내를 확인했다. 잘못된 지역 값은 HTTP 400, 카탈로그 생성 전에는 HTTP 503으로 응답했다. 최종 브라우저 콘솔에서 오류·경고가 없었고, 서버 로그에서 추천·상세 요청 성공을 확인했다.

## 남은 데이터 검수

실제 매장별 원재료·교차접촉·제공량·현재 판매 여부와 사람 승인 영양 매핑은 자료가 추가되어야 확인할 수 있다. 점수와 자동 음식 유형 매핑의 사용자 평가도 후속 검증에 해당한다. 매장 추천 단계는 표준 메뉴 ID와 제공 매장 ID의 연결 자료를 이어서 사용할 수 있다.
